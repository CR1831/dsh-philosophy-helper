# 哲学工作台 · 后续改进方案

> 状态：讨论稿，未实施
> 盘点时点：10 引擎 / 64 人格 / 专用会话 / 追问 / 思维导图 已上线

---

## 一、先说短板：现在它不是"可靠的哲学系统"

功能看起来齐了，但按可靠性排，有四个断层：

### 1. 智能层：没有反馈闭环

- 引擎输出是**自由文本**，无法验证对错
- 没有任何机制回答「这次分析好不好」
- `eval/philosophy_metric.py` 写了 DSPy 评分器，但**从没接进实际流程**
- 换句话说：它写完就完事，没人打分，也没人回炉

### 2. 知识层：只有约定，没有检索

- prompt 里写着「优先用 SEP」，但这只是**口头约定**，agent 真的去查了吗？无从得知
- 引文无法验证，编造与否只能靠 agent 自觉
- 同一个概念在 A 案件分析过，B 案件又从零开始

### 3. 交互层：单向

- 追问的回复**不会回写 findings**，所以「分析结果」和「对话」是两条平行线
- 想深挖某一句，只能靠打字问，没有「对这段继续展开」的入口
- 分析跑起来**不能取消、不能重跑单个引擎**

### 4. 数据层：孤岛

- 案件不能导出（只有面板里能看）
- 5 个案件之后就找不到东西了，没有搜索、没有标签
- 不能对比「同一个问题，顾问模式和辩论模式差在哪」

## 二、可以增加的功能

按「投入产出比」分三档。

### A 档：半天到两天，立刻提升手感

| 功能 | 做法 | 为什么值得 |
|---|---|---|
| **案件导出** | 复用 `mindmap.ts` 的单文件思路，导出 Markdown / 单文件 HTML（含全部引擎正文＋地图）/ DOCX | 现在成果锁在面板里，导不出去等于不能交付 |
| **搜索与标签** | 案件加 `tags: string[]`，面板顶部搜索框按问题/标签/引擎正文过滤 | 5 个案件还无所谓，50 个就废了 |
| **分析取消与重跑** | `POST /cases/:id/cancel` 调 `sessionController.cancel`；单引擎重跑用 `philosophy_case_save` 覆盖 | 跑偏了只能干等，体验很差 |
| **专用会话归档** | 跑完调 `workspaceRegistry.archiveSession` | 会话列表现在会被 5 个 `philosophy-*` 塞满 |
| **轮询换 SSE** | 用 `sessionController.follow` 的流式事件替代 5s/3s 轮询 | 现在是两个定时器叠加，既费又慢 |

### B 档：一周量级，质变

| 功能 | 做法 | 难点 |
|---|---|---|
| **论点依赖图** | 引擎输出增加 `claims: [{id, text, supportedBy, attackedBy}]`，地图改成有向图 | 要改引擎契约，老案件得迁移 |
| **概念谱系库** | 跨案件维护 `concepts.json`：概念 → 定义版本 → 出处 → 用过它的案件 | 概念去重（「自由」和「自由意志」算不算一个） |
| **引文验证器** | 写回时检查每条 `《…》` 是否能在 SEP / ncpssd 检索到，检索不到标红 | 网络请求 + 缓存，中哲篇目尤其难查 |
| **信念地图** | 教练模式下记录用户的每次回答，画出「你说过 A，又说过 B，在 C 处冲突」 | 需要跨轮次的状态存储 |
| **案件模板** | 预置「伦理困境」「概念辨析」「论文审查」「课堂讨论」四套参数（模式＋人格＋引擎） | 简单，主要是设计 |

### C 档：两周以上，方向性

| 功能 | 说明 |
|---|---|
| **本地语料 RAG** | 把 SEP、海德格尔、巴门尼德、ncpssd 资料建索引，检索后再写。这是「知识可靠」的唯一正解 |
| **学习进度系统** | 记录用户掌握/反复出错的概念，生成训练计划 |
| **多案件对比** | 同一问题在不同模式下的结论并排，看模式如何影响答案 |

## 三、建议不做或缓做

- **多人协作**：DSH 是单机环境，没有账号体系，做了也是假的
- **移动端适配**：面板本来就窄，再压到手机尺寸会不可用
- **复杂权限**：单用户，没有意义
- **更多哲学家**：64 位已经超出实际使用量，再加是数字游戏

---

## 四、推荐路线

### 阶段 1（体验闭环，2–3 天）
导出 + 搜索标签 + 取消/重跑 + 会话归档 + SSE

**判据**：能从「开案件」一路走到「导出一份能发给别人的文件」，中间不卡。

### 阶段 2（智能可见，1 周）
引擎结构化输出 + 论点依赖图 + 信念地图

**判据**：地图上的线能回答「谁反驳谁」，而不只是「谁提到谁」。

### 阶段 3（知识可靠，2 周+）
本地 RAG + 引文验证

**判据**：随便抽 10 条引文，能查到出处的比例 > 90%。

## 五、更根本的一件事

现在的哲学 agent，本质是**「prompt + 会话编排」**，不是「有知识、有记忆、能验证」的系统。

所以真正该补的不是功能，是三件事：

1. **可验证的知识源** —— 让「引用」有据可查，而不是靠模型自觉
2. **可回滚的分析过程** —— 每个引擎的输出能单独重跑、对比版本
3. **可积累的用户模型** —— 它记得你在哪类问题上反复绕圈

这三件事做完，功能清单自然会长出来。反过来，只堆功能，它永远是个「看起来很专业的聊天框」。

---

## 六、如果只做一件事

**做案件导出。**

理由：现在所有成果都锁在面板里。导出的那一刻，这个工具才从「演示」变成「能交付的东西」——而且技术上最省力，`mindmap.ts` 的单文件思路可以直接复用。
