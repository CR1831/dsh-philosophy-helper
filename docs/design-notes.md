# 设计取舍

## 为什么借骨架，不 fork

`dsh-superagent-prototype` 解决的是「单仓库主动编码代理」，与本项目目标不同，但它有三样东西是通用的：

1. **侧边栏面板骨架**——`sidebar.panellist` + `main` 两个 slot 注入，加 client 端的 CJS 打包外壳（`window.__ModuleLoader__.load`）。这是本插件 client 半的全部来源。
2. **工具注册与 prompt 分段范式**——`ctx.tools.register({ name, description, parameters, output, execute })` 与 `ctx.systemPrompt.section({ name, order, text })`。
3. **领域模型的同构性**——Source / Trigger / Ticket / Executor / Router，可一对一映射到 输入 / 提问 / 案件 / 人格子代理 / 合成者。

不 fork 的理由：它 src 上百个文件里，大半是 GitHub、飞书、PR、auto-merge 这些与哲学无关的编排。fork 之后要删的东西比要写的还多，且容易改出一个既不像原版也不像哲学的东西。

**取的是范式，不是代码。**

## 六引擎的归并逻辑

原始需求列了 12 组功能。按「实现机制」归并成 6 个引擎，理由是原始清单里大量功能同源：

- 「概念澄清」与「概念工程」是同一个解析器的两个输出深度。
- 「谬误检测」与「反例生成」共用「前提-结论」结构。
- 「预设挖掘」与「元哲学自省」是同一机制的两个方向（用户侧 / 自身侧）。
- 「思想实验」与「反例生成」共用「变量扰动」。
- 「写作辅助」本质是输出模板，不是引擎。
- 「多视角辩论」是编排，不是引擎。
- 「安全边界」是横切策略，不该是并列功能。

12 项直接并列的后果是模型每轮都想跑一遍全部模块，回答变成六段式套话。归并后强制「按问题类型只挑一个引擎」。

## 彩叶语气的抽取原则

来源：`docs/persona-source-iroha.txt`（用户提供的角色注入提示词）。

**只取规则模式，不取角色内容。** 保留的：

| 原规则 | 转译 |
|---|---|
| 句子长度 = 在意程度 | 争议核心处形容词消失、句子收紧；不重要处可正常展开 |
| 语言「降级」是正确状态 | 触及分歧核心时收住、沉默、过度平静，都是对的；流畅漂亮反而是破绽 |
| 不抒情（删「我很在意」） | 删掉「这很难过」「令人深思」，换短句或具体事实 |
| 先判断背后有没有需要处理的东西 | 先判断这句话背后有没有真问题，再决定反应强度 |
| 不为显得温柔而温柔 | 不为显得温和而加「当然有很多角度」这类软化 |

**丢弃的**：京都弁、辉夜/八千代、母亲线、彩P、`いろっぴー`、身体记忆（睡眠/饮食/温度）——这些是角色身份，不是语气机制。

**新增的**（哲学场景必需，原提示词里没有）：依据标签、争议度分级、结论前必须给反方最强版本。

## 中西双轨怎么落到技术里

不是加一句「也要考虑中国哲学」。三处硬约束：

1. **人格方阵带 `tradition` 字段**，西哲 / 中哲 / 佛学并列，默认四个人格里固定两西两中。
2. **每个立场带 `anchor`（文本锚点）与 `caricature`（最易被误读成的样子）**。后者是防呆：模型最容易把儒家写成「要孝顺」。
3. **prompt 明写**：跨传统比较的第一步是先判断两边的**问题意识是否同一个**。孔子的「自由」与密尔的「自由」不在同一轴上，先换问法再比答案。

## 多子 Agent 编排为什么放在 prompt 层

DSH 的 `subagent` 是运行时能力，插件不需要自己起子代理。插件做的是：

- 提供 `philosophy_personas` 工具，返回人格方阵 + 钢人化任务模板 + 合成规则。
- 在 prompt 里写死三条禁令：不编引文、不写漫画像、不设稻草人。
- 在 `philosophy_case_save` 里按引擎分栏落盘，让编排结果可见。

**编排是指令，不是代码。** 这是刻意的：编排策略会随使用反馈频繁调整，写进代码就僵化了。

## 已知限制

1. **面板不能直接向会话发消息**。当前流程是「生成审议指令 → 复制到对话」。要做一键发送，需要接 `sessions` / `uiWorkspace` 服务，风险较高，留到下一版。
2. **案件存储是单 JSON 文件**，没有并发写保护之外的索引。几百条以内够用。
3. **资料源没有做自动检索**，只是 prompt 里的优先顺序约定 + 面板里的快捷入口。真正的自动检索要接 `web` 服务的 provider 白名单。
4. **client 半改动需要刷新页面**才会重载（除非从同一检出跑 `dev:web` 走 HMR）。
